⏳ Batch lifecycle

Persist the job. Observe the state.

Batch is API-only and locally bounded to eight image requests. Its job file contains recovery state and remote IDs, never prompts, keys, or image bytes.

📁
Prepare the output directory

The CLI never creates it implicitly: mkdir -p artifacts/design

Validate, then submit once

codex-image batch submit \
  --provider api \
  --prompt "A luminous rust fox" \
  --output-dir artifacts/design \
  --prefix fox-batch --n 2 \
  --job-file artifacts/design/fox-job.json \
  --dry-run --json

When the plan is correct, remove only --dry-run and submit once. Keep the returned job file; an unknown POST is not permission to submit again.

Read, retrieve, or recover

codex-image batch status \
  --job-file artifacts/design/fox-job.json --json

codex-image batch retrieve \
  --job-file artifacts/design/fox-job.json \
  --wait --max-wait-seconds 300 --json

For unknown outcomes, use explicit batch recover only after read-only remote reconciliation.

🧭 Large runs

Plan first. Approve the exact digest.

Manifest runs make a large set inspectable before billable execution. The run file records paths, IDs, shard state, and plan digest, never prompt bodies.

📁
Prepare the output directory

mkdir -p artifacts/design before planning or executing.

codex-image run plan \
  --manifest assets.jsonl \
  --output-dir artifacts/design \
  --mode batch --parallelism 8 --json

codex-image run batch \
  --manifest assets.jsonl \
  --output-dir artifacts/design \
  --run-file artifacts/design/run.json \
  --approve-plan PLAN_SHA256 \
  --shard-size 8 --wait --json

Do not edit the manifest or run file after approval. Resume durable state; never resubmit assets marked in-flight or outcome-unknown.

When something goes wrong

Read first. Retry second.
